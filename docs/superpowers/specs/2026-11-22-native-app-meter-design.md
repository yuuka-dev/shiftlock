## 1. 目的と理由

**作るもの**: トレイ常駐の `shiftlock.Agent` に，アプリごとの稼働計測を足す．10 秒ごとにプロセスを見て，5 分ごとに「どのアプリがどれだけアクティブだったか・どれだけ CPU を使ったか」を 1 行書く．レポートにはカテゴリ（ゲーム／開発／Adobe）ごとの時間を出す．

**なぜ**:

- いまの記録は「PC を触っていたか」と「ゲームが起動していたか」だけで，何に時間を使ったかがカテゴリでも分からない．
- 次の区切り（減速・一時停止）は「そのアプリの直近の使用率」に対する割合で CPU の上限を決める（★ 固定の % では多コアの PC で効かないため）．その「直近の使用率」をここで記録する．

順番（★）: ① Agent（済み）→ **② 稼働計測（この文書）** → ③ 減速・一時停止・解除．

## 2. ゴール・やらないこと・やってはいけないこと

### ゴール

- Agent が 10 秒ごとに計測し，時計の 5 分の区切りで `log/app-YYYY-MM.jsonl` に 1 行書く．
- `shl app add / remove / list`（Python 版）で exe を登録できる．JSON を手で編集しなくてよい．
- レポートに，カテゴリの帯と日ごとのカテゴリ別時間が出る．アプリ名は出ない．
- 計測を足しても，見張り（tick）の動きとテストベクタ（`tick.json`）は変わらない．

### やらないこと（この区切りでは）

- 減速・一時停止・解除，ジョブオブジェクト，`NtSuspendProcess`（③）．
- Claude Code の「処理中」の判定（hook の `Stop` の追加）．③ の声かけ待ちで使うものなので ③ に送る（☆）．
- ③ の対象の印（どの exe を減速してよいか），アンチチートの警告，対象外の決まり（システム・shiftlock・Claude Code・Discord）．② の登録は**計測のためだけ**で，登録しても何も止まらない（☆）．
- 登録の画面（ウィンドウ・トレイ）．★ 今のところコマンドラインだけ．
- 計測の結果による通知・声かけ．
- ネイティブ版の `shl`（`native/shl`．中身はまだ空）への実装．

### やってはいけないこと

- **プロセスに手を加えること**．この区切りは読むだけ（開くときの権限は問い合わせ用の最小のものだけ）．
- 登録していないアプリの名前を，ログ・`agent.log`・レポートのどこかに残すこと（★ 案 A）．
- レポートにアプリ名を出すこと（★）．
- 計測の失敗で Agent が落ちること，見張りや通知が遅れること．
- `Tick.Run` と `log/pc-*.jsonl` を変えること．
- 文面を C# や Python のコードに直書きすること．

## 3. 作り方の候補と選んだもの

**計測と見張りのつなぎ方**

| 案 | 内容 | 判断 |
|---|---|---|
| **1. 独立した仕事として `Scheduler` に足す** | 10 秒ごとに測ってメモリにため，時計の 5 分の区切りで書く | **採用（★）**．見張りに触れないので，Python 版と一致している今の動きが変わらない．計測が失敗しても通知は止まらない |
| 2. 見張り（5 分の tick）の中で書く | `pc-*.jsonl` と行の時刻がそろう | 不採用．見張りが飛んだ回は区間が伸びる．`Tick.Run` に Python 版に無い処理が混ざる |
| 3. 計測だけ別プロセス | Agent が落ちても続く | 不採用．自動起動・二重起動の仕組みがもう 1 組要る |

**名前つきで残す範囲**

| 案 | 内容 | 判断 |
|---|---|---|
| **A. 登録した exe と自動判定のゲームだけ．ほかは「その他」に合算** | ログが小さく，何を開いたかが残らない | **採用（★）** |
| B. アクティブになった exe を全部 | 細かいものまで全部出る | 不採用（★） |
| C. 登録した exe だけ．ほかは記録しない | 「その他」の時間も見えない | 不採用 |

**カテゴリ**: 固定の `game`／`dev`／`adobe` ＋自動の「その他」（★）．自由な名前は採らない（打ち間違いで別カテゴリができる）．ログは exe 単位なので，後からカテゴリを足すときもログは作り直さなくてよい．

## 4. 何を測り，何を書くか

### 4.1 登録と設定

`shifts.json` に節 `apps` を足す（既定値は Python の `DEFAULTS` と C# の両方に同じ値で持つ）．

```json
"apps": {
  "registered": {"code.exe": "dev", "photoshop.exe": "adobe"},
  "active_input_minutes": 5,
  "active_cpu_percent": 5
}
```

- `registered`: exe 名 → カテゴリ（`dev` か `adobe`）．既定は空．
- ☆ 登録は exe 名で行う（フルパスではない）．Python 版の `shl` は WSL からも使うので実行中のプロセスを一覧できず，パスは手で打つことになるため．同じ名前の別の exe は同じものとして扱う．
- ☆ 名前は小文字・`.exe` つきにそろえて保存する．`shl app add Code dev` も `Code.exe` も `code.exe` になる．比べるときは大文字小文字を区別しない．
- ☆ ゲームは登録しない．いまの判定（`Games`．Steam のフォルダ・`game_dirs`・除外・`game_processes`）で「ゲーム」になった exe が，その exe 名で `game` として記録される．`shl app add <名前> game` は断り，ゲームの設定は設定メニューで行うよう案内する．
- 登録した名前がゲームの判定にも当たるときは，登録のカテゴリを優先する（☆）．
- `active_input_minutes`・`active_cpu_percent`: アクティブの判定の数値（★ 設定で変えられる．既定 5 と 5）．数でない・負の値のときは，その回の計測を失敗にして `agent.log` に書く（黙って既定値にしない．☆）．
- 計測の間隔（10 秒）と書く間隔（5 分）は設定に出さない（☆）．

コマンド（Python 版．`pc/shiftlock/` に役割のモジュールを 1 つ足し，入口は `cli.py`）:

```
shl app add <exe名> <dev|adobe>    登録（既にあればカテゴリを付け替え）
shl app remove <exe名>             登録を外す（無ければその旨を出す）
shl app list                       登録の一覧（カテゴリごと）
```

- `shifts.json` の読み書きは設定メニューと同じ道（省略したキーを書き足さない，`.tmp` → 置き換え）．
- 文面は `ja.py` と `ja_kansai.py` の両方に `APP_` で始まる名前で足す．`shl help` にも足す．
- 登録の変更は，Agent が次に行を書いた後の区間から効く（Agent は 5 分の区間の頭で設定を読み直す．☆）．

### 4.2 10 秒ごとの計測

1 回の計測で取るもの:

| もの | 取り方 |
|---|---|
| 全プロセスの PID・親の PID・開始時刻・CPU 時間（ユーザー＋カーネル）・exe 名 | ★ `NtQuerySystemInformation(SystemProcessInformation)`．失敗したら `System.Diagnostics.Process` |
| 前面のウィンドウのプロセスの PID | `GetForegroundWindow` → `GetWindowThreadProcessId` |
| 最後の入力からの秒数 | いまの `ISystemProbe.IdleSeconds` |
| exe のフルパス（ゲームの判定用） | いまの `QueryFullProcessImageName`．(PID, 開始時刻) ごとに 1 回だけ取って覚える |

- ★ プロセスは (PID, 開始時刻) で識別する（PID の使い回しで別物を同じと見ない）．
- ☆ exe のパスが取れないプロセス（権限が上のものなど）は，フォルダによるゲームの判定には当たらない（`game_processes` の名前の指定と，登録の名前は効く）．取れなかったことも覚えて，同じプロセスで取り直さない．
- **使用率**: 前回の計測からの CPU 時間の増分 ÷（経過時間 × 論理コア数）× 100．☆ **PC 全体を 100%** とする（タスク マネージャーの表示と同じ．③ のジョブの上限も PC 全体に対する割合で効く）．経過時間は単調な時計で測る．
- 前回の計測に無かったプロセスは，開始時刻が前回の計測より後ならその CPU 時間を全部増分に数え，そうでなければ今回を起点にして増分 0 とする．
- **ツリー合計**（★ 子プロセスを含む）: ある exe 名の「ツリー」は，その名前のプロセス全部と，その子孫全部（親の PID をたどる．親の開始時刻が子より後なら親子とみなさない）．同じプロセスは 1 回だけ数える．
- **間が空いたとき**: 前回の計測から 30 秒以上空いていたら（スリープ・Agent の固まり），その回は増分もアクティブの秒数も数えず，起点だけ取り直す（☆）．
- **代替（`System.Diagnostics.Process`）のとき**: 親の PID が取れないので，ツリーは同じ名前のプロセスだけになる．CPU 時間や開始時刻が取れないプロセスは飛ばす．代替に切り替わったことは `agent.log` に 1 日 1 回書く．行には印を付けない（☆）．

### 4.3 アクティブの判定（★）

ある計測の時点で「アクティブなアプリ」は高々 1 つ:

1. 前面のプロセスが属するアプリを決める．☆ **前面のプロセス自身の exe 名**で見る（親はたどらない．エディタから開いたブラウザを開発に数えないため）．登録にあればそのアプリ，ゲームの判定に当たればその exe 名のゲーム，どちらでもなければ「その他」．前面が取れなければ，どれもアクティブでない．
2. そのアプリについて，**直近 `active_input_minutes` 分に入力がある** か **ツリー合計の使用率が `active_cpu_percent` % 以上** なら，アクティブ．「その他」のツリーは，前面のプロセスとその子孫．
3. ☆ ただし入力が `usage.game_idle_minutes`（既定 180 分）無ければ，CPU を使っていてもアクティブとしない（いまの「ゲームを起動したままの放置」と同じ決まりを全部のカテゴリに当てる．寝ている間の書き出しやつけっぱなしのゲームが何時間も積み上がらないように）．
4. アクティブなら，前回の計測からの経過秒数をそのアプリの「アクティブの秒数」に足す．

画面のロック中は，前面がロック画面のプロセスになるので「その他」で，入力が無くなればアクティブでなくなる．特別な扱いはしない．

CPU の記録はアクティブとは別で，登録した exe と動いているゲームは**前面に無くても**使用率を記録する（③ が使う）．

### 4.4 5 分ごとに書く 1 行

ファイルは `log/app-YYYY-MM.jsonl`（月は行の時刻の月）．追記のみ．

```json
{"t": "2026-12-07T21:05:00", "span": 290, "apps": {"code.exe": {"cat": "dev", "act": 240, "cpu": 3.2}, "eldenring.exe": {"cat": "game", "act": 0, "cpu": 0.4}}, "other": 30}
```

| キー | 中身 |
|---|---|
| `t` | 区間の終わりの時刻（時計の 5 分の区切り．秒まで） |
| `span` | その区間で実際に測れた秒数（計測の経過秒数の合計．スリープや起動直後で短くなる） |
| `apps` | exe 名（小文字・`.exe` つき）→ `cat`（`game`／`dev`／`adobe`．書いた時点のカテゴリ），`act`（アクティブだった秒数．整数），`cpu`（測れた間のツリー合計の平均使用率．PC 全体 = 100．小数 1 桁） |
| `other` | 「その他」がアクティブだった秒数（整数） |

- `apps` に載せるのは，その区間に 1 回でも動いていた登録の exe とゲーム．動いていなければ載せない．☆「動いていた」はプロセスが在ったこと（CPU を使っていなくても `act` 0・`cpu` 0.0 で載る．③ が「起動しているが使っていない」を読めるように）．
- 区間に 1 回も測れなかった（`span` が 0）なら行を書かない．測れたが何も動いていなければ `"apps": {}` の行を書く（「測っていた」ことがレポートで分かるように）．
- 時計の 5 分の区切りをまたいだ最初の計測のときに，前の区間の行を書く．`t` はまたいだ区切りの時刻．
- Agent を「終了」や合図で終わらせるときは，たまっている分を書いてから終わる（`t` はその時刻）．落ちたときは最大 5 分ぶんを失う（☆ そのままにする）．
- 同じ `t` の行を 2 回書かない（起動し直しで同じ区切りに 2 回当たったら，後のほうは次の区切りにまとめる）．
- 個人データなのでコミットしない（`log/` は既に対象）．古い月は今の整理（`log/*-YYYY-MM.jsonl` を `retention.log_keep_days` で消す）でそのまま消える．
- 書く前に [data-format.md](../../data-format.md) §1 の表に行を足す．

### 4.5 Python 版の見張りが有効なとき・設定エラーのとき

- タスク `shiftlock-guard` が有効で Agent が見張りを止めている間も，計測は動く（書くファイルが別で取り合わない．☆）．
- `shifts.json` が無い・壊れているときは計測しない（見張りと同じ）．次の区間の頭で読み直す．

## 5. 構成

```
native/
  shiftlock.Core/          計測の計算と行の組み立て（Windows API を呼ばない）
  shiftlock.Core.Tests/    合成の計測の列で確かめる
  shiftlock.Agent/         プロセスの一覧・前面のプロセスを取る側，10 秒の仕事
  shiftlock.Agent.Tests/   取る側を差し替えた流れ
pc/shiftlock/              shl app，設定の既定値，レポートの集計と表示
```

依存の向きは今のまま（`Agent → Core`）．

### 5.1 shiftlock.Core

純粋な計算として置く（`now` と値は引数で受ける）．名前は作る人に任せるが，役割はこの 3 つ:

- **計測の積み上げ**: 「プロセスの一覧・前面の PID・アイドル秒数・ゲームと判定された (PID, 開始時刻) の集まり・時刻・単調な時計の値」を 1 回ぶん受けて，§4.2〜4.3 のとおりに積む．区切りをまたいだら書く行を返す．
- **設定の読み取り**: `apps` の節（登録・数値）と `usage.game_idle_minutes`．
- **行の書き込み**: いまの `Store` のログの追記に揃える（Python 版が読める形）．

ゲームかどうかの判定はいまの `Games` をそのまま使う．

### 5.2 shiftlock.Agent

- ★ ネイティブ呼び出しはインターフェースの裏に置く．プロセスの一覧を取る側は「`NtQuerySystemInformation` の実装」「`System.Diagnostics.Process` の実装」「前者が失敗したら後者に回す組み合わせ」に分ける．前面の PID を取る側も差し替えられるようにする．
- `Scheduler` に仕事 `meter`（10 秒間隔）を足す．前の回が終わっていなければ飛ばす．例外は `Scheduler` が握ってログに書く．同じ失敗を 10 秒ごとに書き続けない（同じ文は 1 日 1 回など）．
- スリープからの復帰では何もしない（次の計測で「30 秒以上空いた」として起点を取り直す）．
- トレイの見た目・メニューは変えない．
- **確かめ用の入口** `shiftlock-agent.exe --meter-once`（☆）: 10 秒あけて 2 回測り，書くはずの行を標準出力に JSON で出す．ファイルは書かない．`NtQuerySystemInformation` が実機で動くかを，本番のフォルダに触れずに見るため．

### 5.3 Python 側

- `config.py` の `DEFAULTS` に `apps`．
- `shl app`（§4.1）．
- レポート（§6）．
- `pc/tools/export_native.py`: Agent が新しく使う文があれば対象に足す（今のところ `agent.log` は英語固定なので，増えない見込み）．

## 6. レポート

読むのは訪問看護の人．アプリ名は出さない（★）．

**集計**（`report.py`）:

- `log/app-*.jsonl` の各行を，`t − span/2` の時刻の「日・時」に入れる．カテゴリごとに `act` の秒を足し，分に直す（1 時間は 60 分で頭打ち）．
- 行数ではなく秒数を足す．
- 乗務の外出区間（いまの `away`）の中の行は数えない（いまのゲームと同じ扱い）．
- ☆ **稼働計測の行がある時間帯は 3 カテゴリとも稼働計測から出し，無い時間帯のゲームは今までどおり `log/pc-*.jsonl` から出す**．計測を始める前の日や，Python 版だけで動かしている環境でも，ゲームの表示は今と同じになる．
- ☆ 「時間帯」の単位は日・時のマス．計測の行が 1 本でも入ったマスは稼働計測だけで出す（2 つの記録を足し合わせない．二重に数えないため）．時の途中で Agent を起動した最初のマスは，起動より前のゲームの分が出ない．
- 「PC を触っていた時間」（青の濃淡・PC の列）は今までどおり `log/pc-*.jsonl` から．変えない．

**表示**（`report_html.py`）:

- ★ マスの下の帯を，カテゴリの色分けにする．いまはゲームが 15 分以上のときオレンジの帯 1 本．これを「15 分以上のカテゴリの帯を並べる」に変える（色はゲーム = 今のオレンジ，開発・Adobe は新しい 2 色．明るい・暗いの両方で見分けがつくこと）．
- マスのヒントに，カテゴリごとの分数を足す．
- ★ 日ごとの列: いまの「ゲーム」の列の隣に「開発」「Adobe」の時間の列を足す．
- 凡例に 2 色を足す．文は `ja.py`／`ja_kansai.py` の `REPORT_*`．
- 「その他」は帯にも列にも出さない（青の濃淡が PC 全体の時間を表している．☆）．

## 7. 確かめ方

テストを先に書く．

1. **Core の単体**: 合成の計測の列（時刻・プロセス・前面・アイドル）に対して，書かれる行が期待どおりか．少なくとも: 前面＋入力あり／前面＋入力なし＋CPU 高い／前面＋入力なし＋CPU 低い／前面でない（`act` は 0，`cpu` は記録）／入力が 180 分無い／PID の使い回し（開始時刻が違う）／子プロセスの合算と重複なし／途中で始まった・終わったプロセス／30 秒以上の間／区切りまたぎ／月またぎ／登録なしで「その他」だけ／登録とゲームの判定が重なる／同じ `t` を 2 回書かない．
2. **Agent**: 取る側を差し替えて，「10 秒の仕事が見張りを呼ばない・見張りの結果を変えない」「一覧の取得が失敗したら代替に回る」「両方失敗しても落ちない」「終了のときにたまった分を書く」．
