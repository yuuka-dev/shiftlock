## 1. 目的と理由

**作るもの**: 強制モードに動作を 2 つ足す．

- `throttle`: 就寝目安（`soft_close`）から最低ライン（`hard_close`）までを 4 等分し，対象のアプリの CPU の上限を「そのアプリの直近の使用率」の 75 → 50 → 25 → 10% に下げる．最低ラインを過ぎても 10% のまま．
- `suspend`: `throttle` と同じ減速をし，最低ラインで対象のアプリを一時停止する．

どちらも出発（「行ってきます」）・「今日休む」・緊急解除で元に戻す．

**なぜ**:

- 今の強制は PC 全体を止める（ロック／スリープ／シャットダウン）だけで，「寝る前にゲームがだんだんやりにくくなる」という中間が無い．
- ★ 上限を固定の % にしない．ジョブの CPU 上限は PC 全体に対する割合で効くので，多コアの PC では固定の % が効かない．だから「そのアプリの直近の使用率に対する割合」にする．

順番（★）: ① Agent（済み）→ ② 稼働計測（済み）→ **③ 減速・一時停止・解除（この文書）**．

## 2. ゴール・やらないこと・やってはいけないこと

### ゴール

- `shl enforce on throttle`／`shl enforce on suspend` で宣言でき，同意の表示に段階の時刻・割合・対象になるゲーム・解除の方法が出る．
- 宣言した乗務で，Agent が段階どおりに上限を下げ，`suspend` なら最低ラインで一時停止する．
- 出発・「今日休む」・`shl kaijo`・`STOP.txt`・トレイの「緊急解除」のどれでも，10 秒以内（トレイは即時）に上限が外れ，一時停止が再開される．
- Agent が落ちても，起動し直したときに，一時停止したままのプロセスを必ず再開する．
- 宣言していない乗務・動作が `lock`／`sleep`／`shutdown` の乗務では，プロセスに一切手を加えない．

### やらないこと（この区切りでは）

- ロック系（`lock`／`sleep`／`shutdown`）との併用（★ 1 乗務 1 動作のまま）．
- 対象の登録や宣言の画面（ウィンドウ・トレイ）．★ 今のところコマンドラインだけ．
- ネットワークやディスク，GPU の制限．メモリの制限．
- ネイティブ版の `shl`（`native/shl`）への実装．
- 出発の判定の追加（位置情報など）．★ 最初の版は `state.json` の「行ってきます」の記録を見る 1 実装だけ．インターフェースにして後から増やせる形にはする．

### やってはいけないこと

- **プロセスを終了させること**（kill）．★ 強制シャットダウン・再起動・ログオフもしない．
- 宣言・同意の無い乗務で，プロセスに手を加えること．
- 対象外のプロセス（§4.3）に手を加えること．
- 一時停止したプロセスを，記録せずに残すこと（止める前に必ず記録する）．
- 減速や一時停止を促す通知・質問・Claude への文脈を出すこと．出してよいのは「宣言済みの強制の予告」と「実行・解除の報告」だけ．
- 宣言の入口を C#・画面・トレイ・hook に作ること．非対話で同意を省く入口（`--yes` など）を作ること．
- 失敗で Agent が落ちること，見張り・計測・通知が遅れること．
- 登録していないアプリの名前を，ログ・`agent.log`・通知に残すこと（区切り 3 と同じ）．
- 文面を C# や Python のコードに直書きすること．

## 3. 作り方の候補と選んだもの

**動作の分け方**

| 案 | 内容 | 判断 |
|---|---|---|
| **1. `throttle` = 減速だけ／`suspend` = 減速＋最低ラインで一時停止** | 保存していない作業が固まるのが嫌な日は `throttle` を選べる | **採用（★）** |
| 2. `throttle` = 減速＋一時停止／`suspend` = いきなり一時停止 | | 不採用（★） |
| 3. 動作は 1 つ | | 不採用（★） |

**ロック系との併用**: しない（★）．宣言の形・同意の表示・`Enforce.Due` がほぼ今のまま使える．実機で減速の効き方を見てから広げる道は残る．

**対象の決め方**

| 案 | 内容 | 判断 |
|---|---|---|
| ゲームも 1 本ずつ足す | 確実だが手間 | 不採用（★「1 本ずつ足すのはきつい」） |
| **ゲームは自動で対象．アンチチートつきを自動で外す．開発・Adobe は足したものだけ** | 手作業は「外す」ほうだけ | **採用（★）** |
| 登録したアプリも全部自動で対象 | エディタや書き出し中のアプリが勝手に遅くなる | 不採用（★） |

**減速と一時停止の仕組み**

| 案 | 内容 | 判断 |
|---|---|---|
| **ジョブオブジェクトの CPU 上限（ハードキャップ）＋ `NtSuspendProcess`** | 上限は OS が守る．子プロセスも自動で入る | **採用（☆．筋のいい道はこれだけ）** |
| 一時停止と再開を細かく繰り返す | ジョブが要らない | 不採用．画面と音がカクつく．Agent が落ちた瞬間に止まったまま残りうる |
| 優先度・EcoQoS を下げる | 安全 | 不採用．PC が空いていれば普通に動くので効かない |

## 4. 動き

### 4.1 段階（★）

`soft_close` を S，`hard_close` を H，D = (H − S) / 4 とする．

| 段階 | 始まり | 上限（基準の使用率に対する割合） |
|---|---|---|
| 1 | S | 75% |
| 2 | S + D | 50% |
| 3 | S + 2D | 25% |
| 4 | S + 3D | 10% |
| 5 | H | `throttle`: 10% のまま ／ `suspend`: 一時停止 |

- 割合の並び（75・50・25・10）は設定 `limit.steps` に持ち，★ 宣言のときに表示して，同意した値を宣言に写して固定する（あとで設定を変えても，その乗務には効かない）．
- ☆ 並びは 4 個ちょうど，1 以上 100 未満，大きい順．そうでなければ宣言を断る．
- ☆ H ≤ S（就寝目安と最低ラインが同じ・逆）のときは段階 1〜4 を飛ばし，H から段階 5 だけ．
- ☆ 段階の時刻は Python（同意の表示）と C#（実行）の両方で計算するので，共有の見本（§7）で揃える．分より下は切り捨てない（秒まで持つ．表示は分）．

### 4.2 基準の使用率と上限

- **基準**（☆）: そのアプリ（exe 名のツリー合計）の，減速を始める前の `log/app-*.jsonl` の行のうち，直近 30 分（`limit.baseline_minutes`）で `act` が 1 以上の行の `cpu` の**最大**．平均にしない（メニュー画面で放置していた時間に引っぱられて，上限が低くなりすぎるため）．
- ☆ 基準は，そのアプリに初めて上限をかけるときに決めて `limit.json` に残し，その乗務の間は変えない（減速中の値で測り直すと，上限が下がり続けるため）．
- ☆ **基準は「元に戻す」では消さない**．Agent の終了や起動し直しをまたいで残し，消すのは乗務日（`limit.json` の `day`）が変わったときだけ．起動し直した Agent は，残っている基準をそのまま使う．
- ☆ 基準に使う行は，そのアプリに初めて上限をかけるより前の行だけ．`limit.json` が失われていて基準が無いときは，`t` が S 以前の行から取り直す．それも無ければ下の「当たる行が無いとき」と同じ．
- ☆ 当たる行が無いとき（段階が始まってから起動した，など）は，上限をかけずに動かし，そのアプリが載った最初の行（最大 5 分後）の `cpu` を基準にする．その行の `cpu` が 0.0 なら，次の行を待つ．
- **上限** = 基準 × 割合 ÷ 100（PC 全体 = 100 の %）．☆ 下は 0.5% で止める（それより低いと，上限を外す操作にも応答しにくくなるため）．
- 上限は 1 つのアプリ（exe 名）につき 1 つのジョブにかける．ツリー全体で 1 つの上限．☆ 同じ exe 名のツリーが複数あっても（窓を 2 つ開いた，など）同じジョブに入れ，1 つの上限を分け合う（基準も exe 名の合計で測っているため）．

### 4.3 対象

ある時点の対象は，次の 2 つを合わせたもの．

1. **ゲーム**（★ 自動）: 区切り 3 と同じ判定（`Games`）でゲームになった exe．ただし次は外す．
   - アンチチートの印が見つかったもの（§4.4）．
   - exe のパスが取れず，アンチチートを調べられないもの（☆ 調べられないものは外す）．
   - `limit.exclude` にあるもの（手で外したもの）．
2. **登録したアプリ**（★ 足したものだけ）: `apps.registered` にあり，かつ `limit.apps` にあるもの．

**対象外**（★ システム・shiftlock・Claude Code・Discord）:

- ☆ 名前の一覧を既定値として持つ（`limit.never`．Python の `DEFAULTS` と C# の両方に同じ値）．少なくとも: Windows のシステム（`system`・`csrss.exe`・`wininit.exe`・`winlogon.exe`・`services.exe`・`lsass.exe`・`smss.exe`・`svchost.exe`・`dwm.exe`・`explorer.exe`・`fontdrvhost.exe`・`sihost.exe`・`taskmgr.exe`），shiftlock（`shiftlock-agent.exe`・`shiftlock.exe`・`shl.exe`・`python.exe`・`pythonw.exe`・`python3.exe`），Claude Code とその足場（`claude.exe`・`node.exe`・`wsl.exe`・`wslhost.exe`・`vmmemwsl`・`vmmem`・`windowsterminal.exe`・`conhost.exe`・`openconsole.exe`・`powershell.exe`・`pwsh.exe`・`cmd.exe`・`bash.exe`），Discord（`discord.exe`），ゲームの配信元（`steam.exe`・`steamwebhelper.exe`・`steamservice.exe`）．
- `shl app limit add` は，この一覧の名前を断る．
- ☆ **子孫に「守る名前」が 1 つでも含まれるアプリは，そのアプリごと手を加えない**（エディタのターミナルで Claude Code が動いている，など．ジョブは子プロセスに自動で引き継がれるので，一部だけ外すことができない）．その回は何もせず，次の回にまた見る．そのアプリについて「対象外のものが動いているので見送った」と，乗務ごとに 1 回だけ知らせる．
  - 「守る名前」は `limit.never` の全部ではなく，狭い一覧 `limit.protect`（既定値: `claude.exe`・`node.exe`・`wsl.exe`・`wslhost.exe`・`discord.exe`・`shiftlock-agent.exe`・`shiftlock.exe`・`shl.exe`）．`conhost.exe` や `cmd.exe` を子に持つだけでは見送らない（ゲームのランチャーが普通に持つため）．
  - 見るのは**子孫だけ**．祖先は見ない（Steam から起動したゲームは祖先に `steam.exe` があるのが普通．上限と一時停止はそのアプリの名前のプロセスとその子孫にだけかかり，祖先にはかからない）．
  - この決まりの結果，ターミナルで `node.exe`・WSL・Claude Code を動かしているエディタは，`limit.apps` に足してあっても見送りになる（Claude Code を巻き込まないことを優先）．`shl app limit add` のときにこの旨を表示する．
- ☆ セッション 0 のプロセス・Agent 自身と同じ権限で開けないプロセスには手を加えない（開けなかったら見送り，`agent.log` に 1 日 1 回）．

**宣言で固定するもの**（☆）: `limit.steps` と `limit.apps`（足したアプリの一覧）は宣言に写す．宣言の後で `shl app limit add` をしても，その乗務には効かない．**外すほうは固定しない**: `shl app limit exclude`／`remove` は，宣言した乗務にもすぐ効く（ゆるめる方向はいつでもできる，という今の考え方に合わせる）．

### 4.4 アンチチートの判定（★ 自動で外す）

Agent が行う（ゲームのフォルダを見るので Windows 側）．

- **フォルダの印**: ゲームの根のフォルダ（ゲームのフォルダ直下の 1 階層目．Steam なら `steamapps\common\<ゲーム>\`）の下を 3 階層まで見て，ファイルかフォルダの名前が `limit.anticheat_markers` のどれかに当たれば「アンチチートつき」．既定値（☆）: `EasyAntiCheat*`・`BattlEye*`・`BEService*`・`BEClient*`・`GameGuard*`・`*.des`・`EAAntiCheat*`・`xigncode*`・`*.xem`・`mhyprot*`・`ACE-*`・`AntiCheatExpert*`・`PunkBuster*`・`pb*.dll`・`vgc*`・`FACEIT*`・`EQU8*`・`nProtect*`・`Denuvo*Anti*Cheat*`．
- **プロセスの印**: そのゲームのツリーの中に，名前が `limit.anticheat_markers` に当たるプロセスがあれば「アンチチートつき」．
- **根のフォルダの決め方**（☆）: exe がゲームのフォルダ（Steam の `common`・`game_dirs`）の下にあれば，そのフォルダ直下の 1 階層目．exe がゲームのフォルダの直下にある（`C:\Games\foo.exe`）ときは，根を決められないので，そのフォルダの直下のファイルとフォルダの名前だけを見る（奥は見ない．隣のゲームの印を拾わないため）．名前の指定（`game_processes`）だけでゲームになった exe は，exe のあるフォルダを根にする．
- 結果はゲームの根のフォルダごとに覚える（Agent が動いている間）．フォルダが読めなければ「調べられない」＝ 対象外．
- **限界**（本人に説明済み）: 一覧に無いアンチチートは見つけられない．見逃すと，そのゲームに上限や一時停止がかかる．そのときゲーム側がどう反応するかは不明．受け皿は，同意の表示の一覧（下）と `shl app limit exclude`．

**同意の前に見せるための書き出し**: Agent は，見たゲームの判定を `limit-games.json` に書く（§5）．`shl enforce on throttle|suspend` の同意の表示と `shl app limit list` が読む．Python 版は WSL からも動くので，動いているプロセスを自分では見られないため．

### 4.5 一時停止（`suspend` の段階 5）

- 対象のアプリのツリーの全プロセスを `NtSuspendProcess` で止める．
- ★ **止める前に** (PID, 開始時刻) を `limit.json` に書く（書けなければ止めない）．★ Agent は起動時に，記録にあるプロセスのうち今も同じ (PID, 開始時刻) で在るものを必ず再開する（`NtResumeProcess`）．
- 1 つのプロセスを 2 回止めない（止めた回数だけ再開が要るため．記録にあるものは止めない）．
- 段階 5 に入った後で起動した対象のアプリも，次の回（10 秒以内）に止める．
- 止まったアプリの窓は「応答なし」になる．保存していない内容は残るが，再開するまで操作できない．同意の表示に書く．
- 再開は，記録にある全プロセスを `NtResumeProcess` → 記録から消す．再開に失敗したプロセスは記録に残し，次の回にやり直す．プロセスがもう無ければ記録から消す．

### 4.6 予告と報告

- ★ 段階ごとに予告 1 回．☆ 各段階の始まりの **5 分前**に出す（段階 5 の一時停止も同じ）．宣言や Agent の起動が 5 分前より後なら，気づいた回に 1 回出す．同じ乗務・同じ段階で 2 回出さない（`notify` の一度きりの仕組みを使う）．
- ☆ 段階の幅が 5 分以下で予告が重なるときは，いちばん近い段階の予告だけ出す．出しそびれた段階の予告を後から出さない．
- 文には，次の段階の時刻と割合（か「一時停止」）と，解除の方法を入れる．☆ **アプリの名前は入れない**（「対象のアプリ」と数だけ．通知は読み上げられることがあり，画面を人に見られることもあるため）．
- 対象のアプリが 1 つも動いていないときは予告を出さない（☆）．
- 報告: 一時停止したとき 1 回，解除したとき 1 回．段階 1〜4 の切り替えそのものは知らせない（予告で知らせてあるため．☆）．
- 通知の方法は，段階 1〜4 の予告が `notify.phase`（既定はトースト），一時停止の予告と報告・解除の報告が `notify.hard`（既定はポップアップ）（☆）．
- ★ **Claude Code の処理中は，声かけを処理が終わるまで待つ**（§4.8）．☆ 待つのは通知だけで，段階の切り替えは時刻どおりに行う（同意した時刻なので）．待つのは最大 10 分．それを過ぎたら出す．

### 4.7 解除

Agent は 10 秒ごとに次を見て，どれかに当たれば**全部を元に戻す**（全ジョブの上限を外す → 全プロセスを再開 → `limit.json` を空にする → 報告を 1 回）．

| きっかけ | 見るもの | `events.log` のメモ |
|---|---|---|
| ★ 出発 | その乗務の `status` が `worked`（「行ってきます」） | `depart` |
| ★ 今日休む | `status` が `yasumi` | `yasumi` |
| 緊急解除 | `STOP.txt` が在る／宣言に `released_at` がある | `kaijo` |
| 取り消し | 宣言が無くなった（`shl enforce off`） | `off` |
| ☆ 時間切れ | 今が `start_latest`（遅くとも出庫する時刻）以降 | `timeout` |
| ☆ Agent の終了 | トレイの「終了」・合図での終了 | （書かない） |
| ☆ 動作が違う | 宣言の動作が `throttle`／`suspend` でない | （書かない） |

- 「全部を元に戻す」で消すのは上限と一時停止の記録だけ．基準（§4.2）は残す．
- どの乗務の宣言を見るか・その乗務の S・H・`start_latest` は，今の見張りと同じ決め方（`current`／`Planner`）に従う．新しい決め方は作らない．`start_latest` は逆算の元なので，必ず H より後になる．
- 「出発」の見方はインターフェース（★）の裏に置く．最初の実装は `state.json` を見る 1 つだけ．
- ☆ 「時間切れ」を足す理由: 「行ってきます」を記録しないまま出かけた・寝過ごしたときに，一時停止が次の日まで残らないようにする．`duration_hours`（N 時間で終わり）は `throttle`／`suspend` では使わない．`shl enforce on suspend 3h` のように時間を付けたら断る．
- ☆ Agent を普通に終了するときも全部を元に戻す（止めたまま Agent がいなくなると，再開する者がいなくなる）．次に起動したとき，宣言がまだ有効なら，その時点の段階からやり直す．
- トレイの「緊急解除」は，今の手順（シャットダウンの中止 → `STOP.txt` → `released_at`）に続けて，10 秒を待たずにその場で元に戻す．
- 解除した後，同じ乗務でもう一度かけ直すことはしない（`released_at` があるか，`STOP.txt` が在る間）．`shl enforce resume` で `STOP.txt` を消しても，今の決まりどおり古い宣言は終わりになる．

### 4.8 Claude Code の「処理中」（★ hook の UserPromptSubmit 〜 Stop）

- hook は今も `UserPromptSubmit` と `Stop` の両方で呼ばれている（`Stop` は稼働記録だけ）．ここに印を足す．
- `UserPromptSubmit` で，プロンプトが Claude に渡るとき（exit 0 で終わる道）だけ，`claude-busy.json` に `{"<session_id>": "<時刻>"}` を足す．キーワードや最低ラインで exit 2 を返す道では足さない（Claude が動かないので `Stop` が来ない）．
- `Stop` で，その `session_id` を消す．
- Agent は「30 分以内の印が 1 つでもあれば処理中」と読む（☆ `Stop` が来なかったときに，ずっと処理中にならないように）．
- 印の読み書きに失敗しても hook は今までどおり動く（**exit 2 にしない**）．`session_id` が無い入力では何もしない．
- ☆ 印は Agent の通知を待たせるためだけに使う．Claude への文脈には何も足さない．

### 4.9 動くための条件

- 実行するのは Agent だけ．☆ **Python 版の見張り（タスク `shiftlock-guard`）が有効でも，Agent が動いていれば減速は動く**（計測と同じで，見張りとは独立した仕事）．Agent が動いていなければ何も起きない．
- ☆ 宣言のとき，`log/app-*.jsonl` の最後の行が 15 分より古ければ「Agent が動いていないようなので，このままでは効かない」と表示する（宣言は断らない）．
- 見張り（`Tick`）の側: 動作が `throttle`／`suspend` の宣言には，`enforce_due`（Python）と `Enforce.Due`（C#）は何も返さない（ロックの予告や実行を出さない）．`enforce_suffix` は，この 2 つの動作のときの文を別に持つ（「N 時間」が無いので）．
- `shifts.json` が無い・壊れているとき，宣言や `limit.json` が読めないとき: 新しく上限をかけたり止めたりしない．**既にかけた上限と一時停止は元に戻す**（☆ 判断できないときは，ゆるめる側に倒す）．
- スリープからの復帰: 次の回で普通に判断する（時間切れなら元に戻る）．
- ☆ リモート接続中・起動直後の猶予（ロック系にある決まり）は当てない．Agent は今リモートを見ていない．

### 5.2 `state.json` の宣言

```json
"enforce": {"action": "suspend", "declared_at": "...", "consented_at": "...", "via": "shl",
```

## 6. 構成

```
native/
  shiftlock.Core/          段階の計算・対象の決定・解除の判断（Windows API を呼ばない）
  shiftlock.Core.Tests/
  shiftlock.Agent/         ジョブと一時停止の操作，アンチチートの判定，10 秒の仕事，起動時の再開
  shiftlock.Agent.Tests/
pc/shiftlock/              宣言（throttle／suspend），shl app limit，hook の印，設定の既定値
```

依存の向きは今のまま（`Agent → Core`）．判断は Core，Windows に触るのは Agent．

### 6.1 shiftlock.Core

純粋な計算として置く（`now` と値は引数で受ける）．名前は作る人に任せるが，役割はこの 4 つ:

- **段階**: 計画（S・H・出庫の時刻）・宣言・今の時刻から，今の段階と次の段階の時刻・割合を返す．
- **判断**: 「宣言・乗務の状態・`STOP.txt` の有無・今の `limit.json`・動いている対象のアプリ（ツリー・ゲームか・アンチチートの判定）・直近の計測の行・Claude の処理中か」を 1 回ぶん受けて，「すること」の並びを返す（上限をかける／変える／外す，止める／再開する，予告・報告を出す，`runs` に足す，全部を元に戻す）．
- **対象の決定**: §4.3 の決まり（対象外の名前，ツリーに対象外が含まれる，`limit.apps`・`limit.exclude`，宣言に固定した一覧）．
- **設定と記録の読み書き**: `limit` の節，`limit.json`，`limit-games.json`，`claude-busy.json`．書き込みは今の `Store` の道（`.tmp` → 置き換え）．

`Enforce.Due` は，動作が `throttle`／`suspend` のとき何も返さないようにするだけ（§4.9）．

### 6.2 shiftlock.Agent

- ★ ネイティブ呼び出しはインターフェースの裏に置く．「プロセスをジョブに入れる・上限を変える・外す」「プロセスを止める・再開する」「ゲームのフォルダの印を探す」を差し替えられるようにする．
- プロセスの一覧と前面・ゲームの判定は，区切り 3 の `MeterSampler` と同じ取り方を使う（☆ 同じ 10 秒の回の一覧を使い回して，一覧を 2 回取らない．ただし減速の失敗で計測が止まらないよう，例外は別々に握る）．
- ★ 一覧は `NtQuerySystemInformation`，失敗時は `System.Diagnostics.Process`（区切り 3 のまま）．☆ **代替の経路（親の PID が取れない）のときは，新しく上限をかけたり止めたりしない**（ツリーが分からず，対象外のプロセスを巻き込むかを確かめられないため）．元に戻すほうは行う．
- ジョブの操作と一時停止に，管理された代替は無い．失敗したらそのアプリは見送り，`agent.log` に 1 日 1 回，本人には「できなかった」を 1 回知らせる．
- **起動時**: 見張りや計測を始める前に，`limit.json` の一時停止を再開する（§4.5）．残っている上限の扱いは下の **要確認**．
- **終了時**: 全部を元に戻す（§4.7）．計測の `Flush` より前に行う．
- トレイ: 「緊急解除」に，その場で元に戻す手順を足す．メニューの項目は増やさない．宣言・再開・設定は置かない．
- **確かめ用の入口**（☆）: `shiftlock-agent.exe --limit-once`．今の設定とフォルダで判断を 1 回行い，「すること」の並びを標準出力に JSON で出す．プロセスには手を加えない．本番のフォルダは断る（`--tick-once` と同じ）．

### 6.3 **要確認**（実装の前に，実機で下調べする）

設計のうち，Windows の実際の動きに懸かっている点．計画の最初のタスクを下調べ（捨てる試しのコード．合成の対象として自分で起動した `notepad.exe` や CPU を回すだけの小さなプログラムを使う．本番のフォルダ・本人のゲームには向けない）にして，結果をこの文書に書き足す．

1. **Agent が落ちた後，残った上限を外せるか**．ジョブに名前を付けておけば起動し直した Agent が名前で開ける，というのが望む形．だが，最後のハンドルが閉じると名前で開けなくなる可能性がある（その場合，上限はそのアプリが終わるまで残る）．
   - 開けるなら: 起動時に `limit.json` の `capped` のジョブを開いて，上限を外す．
   - 開けないなら（☆ 代わりの案）: 起動時に `capped` に載っていたアプリがまだ動いていれば，「前回の上限が残っているかもしれないので，アプリを起動し直すと戻る」と 1 回知らせる．加えて，Agent の未処理の例外の受け口で上限を外すことを試みる．
2. **既に別のジョブに入っているプロセス**（Steam が起動したゲームなど）を，入れ子のジョブに入れて上限をかけられるか．かけられないものは見送る．
3. **上限の効き方**: 多コアの PC で，「基準 × 割合」の上限が体感と計測の `cpu` の両方で効くか．上限の最小の刻み．
4. **一時停止と再開**: 窓を持つアプリを止めて再開したとき，元どおり動くか．止めている間に起きること（音・「応答なし」の表示）．
5. 権限が上のプロセスを開こうとしたときの失敗のしかた．

1 で「開けない」と分かったら，本人に伝えてから進める（Agent が落ちたときの戻し方が変わるため）．

### 6.4 Python 側

- `enforce.py`: `ENFORCE_ACTIONS` に 2 つ足す．宣言は今と同じ入口（対話の `y` ＋ Windows のダイアログ）．`throttle`／`suspend` のときの同意の表示（下）．時間の指定は断る．`enforce_due` は何も返さない．`enforce_suffix`・`enforce_status_text` の表示（`ENFORCE_LABEL`・`ENFORCE_TERMS_WHAT` に 2 つの動作を足す．C# も `ENFORCE_LABEL` を引くので書き出し直す．この 2 つの動作では「N 時間」を出さない）．
- **同意の表示**（`enforce_terms`）に出すもの: 動作／段階 1〜5 の時刻と割合／「割合は，そのアプリの直近の使用率に対するもの」／対象になるゲームと，アンチチートで外したゲーム（`limit-games.json` から．直近 30 日に見たもの）／対象に足してあるアプリ／アンチチートの判定には見逃しがありうること／`suspend` なら「止まったアプリは再開するまで操作できない．保存していない内容は先に保存する」／いつ戻るか（出発・今日休む・出庫の時刻）／解除の方法／Agent が動いていないようならその旨．
  - ☆ `throttle`／`suspend` は，注意を出して `y` をもらう動作（`CAUTION_ACTIONS` と同じ扱い）にする．
- `shl app limit`（`apps.py` に足す．入口は `cli.py`）:

```
shl app limit add <exe名>        登録済み（dev／adobe）のアプリを対象に足す
shl app limit remove <exe名>     対象から外す
shl app limit exclude <exe名>    ゲームを対象から外す
shl app limit include <exe名>    外したゲームを戻す
shl app limit list               足したアプリ・外したゲーム・最近見たゲームの判定
```

  - `add`: 登録に無い名前，対象外の名前（`limit.never`）は断る．★ **足すときにアンチチートの警告を出す**（「アンチチートのあるアプリに上限や一時停止をかけると，切断などが起きることがある」）．
  - ☆ `add` と `include`（きつくする方向）は，対話できる端末からだけ（宣言と同じ判定）．`remove`・`exclude`・`list` はどこからでも．
  - 名前のそろえ方・`shifts.json` の読み書きは `shl app add` と同じ道．
- `hook.py`: §4.8 の印．**Git Bash 経由（Windows 版）と WSL 経由の両方で，exit 2 にならないことを確かめる**．
- `config.py`: `DEFAULTS` に `limit`．検証（`limit` が辞書であること，`steps` の形）．
- 文面: `ja.py` と `ja_kansai.py` の両方．Agent が出す文は `pc/tools/export_native.py` の対象のキーに足し，書き出し直してコミットする．`shl help` にも足す．
- レポート: 強制の実行の欄に，新しい 2 つの動作の名前が出るようにする（ラベルを足すだけ．欄の形は変えない．☆）．
