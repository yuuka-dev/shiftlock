# shift-lock v11

乗務前の睡眠を守るための見張り役。**PCの操作は一切せえへん（シャットダウンもしない）**。やるのは通知と、最低ライン以降の Claude Code の新規プロンプト拒否だけ。

## 考え方

```
出発目安   = 出庫目標 20:00 − 準備 1:30           → 18:30
最終出発   = 出庫最終 22:30 − 準備 1:30           → 21:00
就寝目安   = 出発目安から「目標睡眠 5h」を逆算     → 13:30
最低ライン = 最終出発から「最低睡眠 4h」を逆算     → 17:00（ここから Claude Code をロック）
就寝準備   = 就寝目安の 40 分前                    → 12:50
```
- 逆算するときは `no_sleep`（火曜の訪問看護・木曜のヘルパー 10–11 時）を「寝られへん時間」として除外する。
  例）火曜に 8h 寝たいなら 11:00–18:30 で 7.5h、足りない 30 分は 9:30–10:00 に回す → 就寝 9:30
- 帰宅時刻（7時か9時か）は計算に使わない。出発から逆算してるから関係ない。

| フェーズ | Claude Code | Windows |
|---|---|---|
| 就寝準備（12:50〜） | 「20〜30分級の処理はもう投げんとき」＋ Claude に長いタスクは確認させる | トースト 1 回 |
| 就寝目安後（13:30〜） | 警告（ブロックはしない） | トースト 30 分おき |
| 最低ライン（17:00〜22:30） | **新規プロンプト拒否**（実行中の処理は止めへん） | ポップアップ 10 分おき |
| 「起きた」後 | 出発 15 分前にリマインド | 同じ |
| いつでも | 連続 2h で「そろそろやめよ♡」、以降 30 分おき | ゲーム/PC 連続 2h で同じ（ゲームを起動したまま 3 時間触らんかったら離席扱い） |

通知は **PC を触ってる時だけ** 出る（離席中・寝てる間に溜まらんように）。

## 乗務日の決まり方

1. **曜日ルール**（既定: 月〜土が出勤、日曜休み）
2. **カレンダー**（Google カレンダーの予定名に「休み/公休/有給」→休み、「出勤」→出勤。キーワードは変更可）
3. **手動の例外**（下の『11/5 休み』や設定メニュー）… 一番強い

日付を毎回書く必要はない。普段と違う日だけ例外として入れる。

### Google カレンダー連携
1. Google カレンダー（PC のブラウザ）→ 対象カレンダーの「⋮」→ **設定と共有** → **iCal 形式の秘密のアドレス** をコピー
2. `settings.cmd` → `11` → `a` で追加（名前・アドレス・キーワード）→ `y` で保存して今すぐ同期
3. 以後は 5 分おきの見張りのついでに **60 分ごと** に自動同期（`sync_minutes`）。ネットが落ちてても前回分で動く

- **複数のカレンダー**を同時に読める（`calendar.sources`）。同じ日に「休み」と「出勤」が食い違ったら **上のソース** が勝つ（手動の例外日はさらに優先）。1 本が落ちても他は更新され、落ちた分は前回の内容で続く。`状況` にソースごとの最終同期とエラーが出る
- ソースごとに「休み」「出勤」の言葉を変えられる（例: 通院用のカレンダーは「通院」を休みに）。旧設定の `ics_url` 1 本もそのまま動く

- 終日予定・時刻つき予定・複数日にまたがる終日予定に対応。**繰り返し予定は初回の日だけ**（毎週の公休は曜日ルールで書く）
- 秘密のアドレスは「知ってたら誰でも予定を読める URL」。人に見せたら Google 側でリセットしてな（`shifts.json` を共有しない）

### 自動整理（1 日 1 回）
| 対象 | 残す期間（`settings.cmd` → `13` で変更） |
|---|---|
| 手動の例外日・休み/起きた の状態 | 60 日 |
| 活動ログ（`log/*.jsonl`、月単位で削除） | 180 日 |
| `events.log` | 365 日 |
| カレンダーのキャッシュ | 過去 60 日〜未来 180 日（同期のたびに作り直し） |

## 設定の変え方（JSON を直接いじらんでええ）

`settings.cmd` をダブルクリック → 番号を選んで Enter（Enter だけなら今のまま）→ `s` で保存。
例外日（`12`）はその場で保存される。それ以外は `s` を押すまで反映されへん。
言葉づかい（`20`）は 標準語 / 関西弁（既定） から選べる。保存した次の動作から変わる（Claude Code の hook も）。淫夢語録（`shiftlock/i18n/inm.py`）はリポジトリでは配ってへん。自分で書いて置いた環境でだけ選択肢に出る（キーは `ja.py` と同じ名前で、足りん分は標準語で出る）。
レポートの締め日（`16`）を 0 にすると、締め期間やなくて 1 日〜月末の月単位になる。途中経過のレポートも締め日（月末）までの行が出る。

## 解除ワード・予定ワード（Claude Code のプロンプトにこれだけ打つ。Claude には送られへん）

| ワード | 効果 |
|---|---|
| `今日休む` / `休む` | 直近 24h 以内の乗務を休みに。ロックも警告も消える |
| `やっぱ出る` | 休みを取り消し |
| `行ってきます` / `出発` | 今日の乗務を出発済みに（通知・ロック・Claude の拒否が止まる） |
| `今日休む 有給` / `11/2 休んだ 有給` | 同じく休みにするけど **有給の印** を付ける（当日欠勤の目安に数えへん） |
| `11/2 有給` / `今日 有給` / `11/2 有給なし` | 休みの記録に後から有給の印を付ける／外す（休みの記録がある日だけ） |
| `休んだ` / `昨日休んだ` / `11/2 休んだ` | 終わった乗務の事後報告（休んだ）。日付なしは「直近に聞かれた乗務」か「直近に終わった乗務」 |
| `出た` / `11/2 出た` | 終わった乗務の事後報告（出た）。休みの日なら出勤の例外日にもなる。`出た` に続けて文があると普通のプロンプト扱い |
| `ねる` / `ねるわー` / `おやすみ` | 寝た時刻を記録（そこから数える）。語尾の `ー` `！` `ぁ` `♡` とかは無視する |
| `おきた` / `おきたぁ！` / `おはよう` | 起きた扱いにしてロック解除 → 出発リマインドに切り替え（`ねる` があれば何時間寝たかも出る） |
| `状況`（`閉店` でも可） | 今日の時刻と 2 週間の予定を表示 |
| `予定` | 2 週間の出／休を表示 |
| `11/5 休み`（`11/5 休み 通院` のようにメモも可） | 予定の休みを登録 |
| `明日 出勤` / `11/8 出勤` | 休みの曜日に出勤を登録 |
| `11/5 戻す` | 例外を消して曜日ルールに戻す |

`今日休む` は「当日の欠勤」として記録に残る（レポートの「休」・今月の休み回数）。前もって決まってる休みは `11/5 休み` かカレンダーで入れる（こっちは欠勤扱いにならへん）。
出庫最終（22:30）のあとに `今日休む` を打ったときは、翌日やなくて **今日の乗務** が休みになる（事後報告扱い）。

### 当日欠勤の目安
直近 **24 乗務** のうち、有給の印が無い当日欠勤（`今日休む` / `休んだ`）が **5 回以上** になったら、`今日休む` の返事と `状況` に「！」が出て、レポートの「当日欠勤」タイルが赤枠になる。
会社が有給に振り替えてくれた分は `今日休む 有給` か後から `11/2 有給` で印を付けると数えへん。数（乗務数・回数）は `settings.cmd` → `21`（回数を 0 にすると注意なし）。

### 未確認の乗務（出た？休んだ？）
終わった乗務に『出た』『休んだ』『行ってきます』のどれも無いと **未確認** になる。乗務の翌朝以降に PC を触ったとき、1 回だけ「出た？休んだ？」と聞く（トースト、または Claude Code の返事の最後に一言）。返事は `出た` / `休んだ` を打つだけ（日付なしなら聞かれた乗務）。
- 起きた記録（`おきた` や自動判定）がある乗務は「出た」とみなして聞かへん（`settings.cmd` → `18` で変更）
- 聞くのは **1 日 1 件**（新しい乗務から。残りは `shl kakunin`）。v11 を入れた日より前の乗務は従来どおり「出」扱い
- 未確認のままの日はレポートで「出?」になる（出た前提で集計）。一覧は `状況` か `shl kakunin`
- 聞かれるのが嫌なら `18` で「聞かない」に。`状況` の表示だけ残る


### 普段の話し言葉でも拾う
`おうちかえった！ねむねむだからスヤリンコする！ｗ` → 帰宅・就寝を記録。**こっちはプロンプトを止めへん**（Claude は普通に返事して、記録したことに一言触れる）。違ったら `今のなし`（1 時間以内）で取り消し。
- 拾う: ただいま／家帰ってきた／帰宅、寝る／ねるわ／スヤ〜／おやすみ／布団入る／即寝／寝落ち、おきた／おはよ／目が覚めた
- 拾わへん: お願いごと（〜して・〜て ほしい・前に・？ など）、寝れない／起きれへん、寝たら〜／起きたら〜、眠いだけ、80 文字超・複数行、`ねるねるねるね`
- `起きたけどまた寝る` みたいに両方あるときは後ろのほうを採用
- 半角カナ・カタカナ・全角英数は揃えてから判定（`ｵﾔｽﾐ` = `オヤスミ` = `おやすみ`）

### わからん言い方は聞いて覚える
`おやすーﾑｷﾞｭ` みたいに「それっぽいけど決めきれへん」ときは、Claude が返事の最後に「寝るってこと？（うん／ちゃう）」と一言聞く。

| 返事 | どうなる |
|---|---|
| `うん` / `そう` / `せや` / `はい` / `ok` | 記録（時刻は**元の発言の時刻**）＋その言い方を覚える。次からは聞かずに拾う |
| `ちゃう、起きた` / `ちゃう寝る` みたいに別の意味を添える | そっちで記録＋そっちとして覚える |
| `ちゃう` / `違う` / `いや` | 何もせず、その文を「反応せんでええ言い方」として覚える |
| それ以外（普通に次の話） | 質問は取り下げて普通に進む |

- 聞くのは **30 分に 1 回まで**、返事を待つのは 20 分まで
- 覚えた言い方は `settings.cmd` → `15` / `shl learned` で一覧、`shl unlearn おやすーむぎゅ` で忘れる、`shl learn neru ばたんきゅー` で先に教えとくこともできる（種類は kitaku / neru / okita / none）

### どこから使えるか
| 場所 | 使い方 |
|---|---|
| Claude Code（**WSL 版・Windows 版どっちも**） | プロンプトに `ねる` `おきた` `今日休む` `11/5 休み` など。hook はユーザー設定（`~/.claude/settings.json`）に入るので **起動ディレクトリはどこでも効く**。Windows 版は `wsl.exe` 経由で同じ本体を呼ぶ |
| pwsh / Windows PowerShell（どのディレクトリでも） | `shl`（日本語のコマンド一覧）`shl status`（状態）`shl itte`（行ってきます）`shl kakunin`（未確認の乗務）`shl yasumi 11/2` / `shl deru 11/2`（事後報告）`shl neru 23:30` / `shl okita 11/7 7:00`（寝た・起きた時刻を後から足す。下の「睡眠の記録」）`shl settings` `shl day off 11/5 通院` `shl report 14` `shl app add <exe> <dev|adobe>` / `remove <exe>` / `list`（時間を測るアプリの登録。開発・Adobe。ゲームは自動） `shl sync` / `neru` `okita` `yasumi` `deru` `yotei` / `scan-games` `show-games`（`install-profile.ps1` で登録） |
| iPhone | ショートカットで `ねる` `おきた` `ただいま` と気分（下の「気分の記録」） |
| ダブルクリック | `neru.cmd` `okita.cmd` `yasumi.cmd` `deru.cmd` `status.cmd` `settings.cmd` `report.cmd` `scan-games.cmd` `kaijo.cmd`（強制の緊急解除） |

Claude Code の外からは `yasumi.cmd` / `deru.cmd` / `okita.cmd` / `status.cmd` / `settings.cmd` をダブルクリック（デスクトップにショートカットを置くとええ）。
ターミナル派なら `shiftlock.cmd day off 11/5 通院` / `day work 11/8` / `day rm 11/5` / `day list` / `sync` も使える。

- **`ねる` を記録してたら**: そこから PC を触る（or Claude Code を使う）までを睡眠として数えて、4h 以上なら自動で『起きた』
- **自動『起きた』**: PC を触ってない時間が最低睡眠（既定 4h）以上あったら、勝手に『起きた』扱いになる（帰ってすぐ寝た日も OK）。控えめに数えるので、足りひん判定のときは手で `起きた` を打つ
  - 前日が乗務なら、帰宅の最遅時刻（`home_by_latest` 既定 09:00）から数える。iPhone で `ただいま` を記録してたらその時刻から
  - ご飯・外出で 4h 以上 PC を離れると誤判定もありえる。気になるなら `settings.cmd` → `14` →「2) ねるを記録したときだけ」
  - 訪問・ヘルパーの時間帯は数えない／途中で Claude Code を使ってたらそこで区切る
  - `settings.cmd` → `14` でオン/オフ・時刻・時間を変更
- `起きた` のとき、PC の記録で直近にまとまった離席（2.5h 以上）がなかったら「ほんまに寝た？」と一言出る。解除はされる。
- 休み・起きたは全部 `events.log` に残る（今月の休み回数は `状況` で見える）。

## 訪看さん向けレポート

- **自動**: 毎週火曜 9:00 に `reports\` に作る（PC が寝てて逃したら起きたときに実行）。締め日（既定 20 日）区切りで、今の期間の途中経過と前の期間の確定版の 2 本。HTML と PDF（A4 横 1 枚、Edge で変換）
  - 例: `report_2026-10-21_2026-11-20.pdf`
  - 締め期間の終わりから **3 か月** 経ったものは自動で削除（`settings.cmd` → `16` で締め日・保存期間を変更）
- **手動**: `report.cmd` / `shl report` で同じものを今すぐ作って PDF を開く。`report.cmd 14` / `shl report 14` なら直近 14 日の HTML
- 曜日・時刻を変えるなら `install-task.ps1 -ReportDay Monday -ReportTime 08:30`
- **記録を始める前の日は乗務欄を空欄**にして、出勤回数にも数えない（勝手に「出」にしない）ダミーデータでの見本は `sample-report.png`（`tools/make_sample_report.py` で架空のデータから作る。列や見た目を変えたら作り直す）。

- 縦＝日付、横＝時間帯。青の濃さ＝その 1 時間に PC を触ってた分数、オレンジの線＝ゲーム、黒点＝Claude Code
- 灰色＝乗務で外出中、斜線＝記録なし、点線枠＝訪問の時間帯
- 右側: 乗務（出/出?/休）・寝た時刻・起きた時刻・睡眠・PC/ゲーム時間・Claude 回数・メモ（覚醒長／低活動）。「出?」は本人の確認が無い乗務（出た前提で集計）
- 何も触れない日は「ほぼ空白＋低活動」、寝ずに動いてる日は「横一列が濃い青＋覚醒長」として出る
- 寝た／起きた／睡眠は **自分で記録した `ねる` `おきた` だけ** から出す（下の「睡眠の記録」）。PC を触ってない時間からの推定はせえへん

#### 睡眠の記録
- 記録のしかたは 3 つ: Claude Code に `ねる` / `おきた`、`shl neru` / `shl okita`（`neru.cmd` / `okita.cmd`）、iPhone のショートカット。乗務のない日のぶんもレポートに出る
- **記録が無い日は空欄のまま**。推定で埋めへんし、「記録してへんで」みたいな催促もせえへん。しんどくて押せんかった日は空欄でええ（空欄＝寝てない、という意味やない。レポートの下にもそう書いてある）
- **後から足せる**: `shl neru 23:30`（今日の 23:30。まだ来てへん時刻なら昨日）、`shl okita 11/7 7:00`、`shl neru 昨日 22時半`。だいたいの時刻でええ。寝た時刻だけ・起きた時刻だけでも残る（睡眠の長さは両方そろった分だけ出る）
- **間違えたら消せる**: 同じ時刻の後ろに `取消`（`shl neru 11/7 23:30 取消`）。iPhone で押し間違えた分も同じやり方で消える。話し言葉から拾われた分は今までどおり `今のなし`
- 後から足す記録はレポート用だけで、ロック・乗務の状態・強制モードには何も影響せえへん
- `ねる` から 24 時間以内に `おきた` が無いときは 1 つの睡眠にせえへん（間が抜けてるとみなして、寝た時刻・起きた時刻を別々に出す）。2 時間以内の `ねる` の言い直しは後のほう、`おきた` の押し直しは最初のほうを採る
- 自動の『起きた』（PC を触ってへん時間からの判定）は乗務前のロック解除のためのもんで、睡眠の記録には数えへん
- 「覚醒長」は今までどおり PC の記録だけで付く（まとまった離席が 3 時間未満の日）。丸一日 PC を触ってへん日には付かへん

記録されるもの（すべて `shift-lock\log\` にローカル保存、外部送信なし）:
- `pc-YYYY-MM.jsonl` … 5 分ごとのアイドル秒数とゲーム起動有無（どのアプリかは記録しない）
- `claude-YYYY-MM.jsonl` … プロンプトを送った時刻だけ（本文は記録しない）
- `events.log` … 休む／起きた

乗務明けの除外は「出発目安〜翌朝 `shift_end_earliest`（既定 07:00）」。変えたいときは `shifts.json` に `"shift_end_earliest": "08:00"` のように足す。

## 強制モード（寝る前に PC を止める。本人が予約したときだけ）

ADHD 向けの自縛用。**既定はオフ**で、本人が `shl enforce on` を自分で実行し、表示された内容に `y` で同意した乗務にだけ効く。最低ライン（最低睡眠 4h を切る時刻）以降に PC を触ったら 15 分前に予告してから、PC を **ロック**（既定）／スリープ／シャットダウンする。

```powershell
shl enforce on            # 今日の乗務に予約（ロック 2h）。内容を見て y → Windows のダイアログで「はい」
shl enforce on lock 3h    # 時間を変える / shl enforce on shutdown 2h
shl enforce               # 状態（宣言・実行回数・STOP.txt）
shl enforce off           # 取り消し（最低ラインに入ってからは解除扱いで記録に残る）
shl kaijo                 # 緊急解除（= kaijo.cmd をダブルクリック）
shl enforce resume        # 解除後に再開（STOP.txt を消す）
```

- **目的は寝る前に止めること**。予告（最初に PC を触っている状態で出す）から 15 分後に実行、戻ってきたら 5 分の予告のあとまた実行。最初の実行から **2 時間**（`shl enforce on lock 3h` や `settings.cmd` → `19` で変更）経ったら、まだ最低ライン後でも何もしない
- **緊急解除は 2 つ**: `kaijo.cmd`（`shl kaijo`）と、実行フォルダに `STOP.txt` を置く（エクスプローラーだけで可。中身は何でもええ）。どちらも記録に残り、レポートに回数が出る。再開は `shl enforce resume`
- 止まる条件: 休み（`今日休む`）、出発済み（`行ってきます`）、起きた（`おきた` は **寝た記録（『ねる』か 2.5 時間以上の離席）があるときだけ** 効く）、`STOP.txt`、起動から 15 分以内、離席中、時間切れ、1 乗務 6 回
- **Claude Code の hook からは操作できへん**（`強制` と打っても普通のプロンプト。キーワードは無い。『今のなし』も強制の状態には触らへん）。宣言 `shl enforce on` は端末の `y` と Windows のダイアログの「はい」の両方が要るので、パイプや擬似端末では通らへん。解除の方向（`off` / `kaijo` / `resume` / `STOP.txt`）は安全側なので端末なしでも効く。強制を促す通知も出さへん。出るのは予約済みの乗務の予告と実行・解除の報告だけ
- 同意した内容（action・時間・予告の分・回数）は宣言に固定される。あとで `19` の既定値を変えても、その乗務には効かへん
- 離席して戻ってきたら、何時間たっていても **必ず予告からやり直し**（戻った直後に黙ってロックされへん）。ロック直後に誰も触ってなければ再予告もせえへん
- `kaijo.cmd` は予約済みシャットダウンの中止を最初にやる。`guard.ps1 -DryRun` は強制の状態を進めへん（実機確認に使える）
- Parsec などリモートの検出は未対応（遠隔操作中でも発動する）。高速スタートアップが有効やと「シャットダウン → 電源オン」で起動直後の 15 分ガードが効かへん可能性がある（要確認。再予告 5 分は残る）
- スリープ／シャットダウンは **遠隔（Parsec）から戻せへん**。Parsec で触る運用なら `lock` だけにしとく。シャットダウンは 60 秒の猶予のあと未保存の作業ごと落ちる（60 秒以内なら `kaijo.cmd` で中止できる）
- 予告の音は `settings.cmd` → `17` の「強制の予告」

## 通知音（任意の音声ファイル）

通知の種類ごとに WAV / MP3 / M4A / WMA などを指定すると、通知と同時に鳴る（トーストの既定音は消える）。未指定なら今までどおり。離席中は通知自体が出ないので鳴らない。

- `settings.cmd` → `17` で種類（全部の既定 / 就寝準備 / 就寝目安後 / 最低ライン / 出発目安 / 最終出発 / 連続稼働 / 自動『起きた』）ごとにパスを設定。音量（0〜1）と最長秒（既定 20 秒で打ち切り）も変えられる
- 同じタイミングに複数の通知が出るときは **強い方の音だけ** 鳴る（強制の予告 > 最低ライン > 最終出発 > 乗務の確認 > 就寝準備 > 就寝目安後 > 出発目安 > 自動『起きた』 > 連続稼働）。音を鳴らしたトースト以外は Windows の既定音のまま
- ファイルが無いときは鳴らさず通知だけ出して、`guard.log` に 1 日 1 回書く
- 試すときは `powershell -ExecutionPolicy Bypass -File .\guard.ps1 -TestNotify -Sound "C:\path\to\alarm.mp3"`（`-Sound` を省くと `notify.sound.default`）
- フルスクリーンのゲーム中でトーストが見えへんときでも音は聞こえる

## 気分の記録（iPhone → レポート）

5 段階・上下両方向: `−2 どん底 / −1 しんどい / 0 ふつう / +1 アゲ / +2 止まらん`
iPhone のショートカットが iCloud Drive の `Shortcuts/mood.csv` に 1 行ずつ追記 → iCloud for Windows で PC に同期 → レポートの「気分」列とメモ一覧に出る。

### iPhone（1 個作って複製するだけ）
1. ショートカット App → ＋ で新規
2. アクションを順に追加（検索欄で探す。日本語名は iOS のバージョンで多少違う）
   - **日付**（Date）… 「現在の日付」のまま
   - **日付をフォーマット**（Format Date）… 日付形式「カスタム」→ `yyyy-MM-dd HH:mm`
   - **テキスト**（Text）… `［フォーマットされた日付］,-1,`（最後のカンマまで入れる）
   - **テキストファイルに追加**（Append to Text File）… ファイルパス `/mood.csv`、「新規行を作成」オン
   - （任意）**通知を表示** … `記録したで ▼-1`
3. 名前を `▼-1` にして保存 → 長押し「複製」で `▼▼-2` `・0` `▲+1` `▲▲+2` を作り、テキストの数字だけ変える
4. 睡眠用に 3 個（PC を触らずに寝る日用。6 時帰庫 → 7 時に帰って即寝、みたいな日）: テキストを `［日付］,neru,` / `［日付］,okita,` / `［日付］,kitaku,` にしたものを `ねる` `おきた` `ただいま` として複製
   - `ただいま` は、オートメーション →「到着」（自宅）で自動実行にもできる（iOS の設定で「すぐに実行」を選べるかはバージョン次第、要確認）
   - 後から足す用にもう 2 個作っとくと楽: 先頭の **日付** を「**入力を要求**（日付と時刻）」に変えたものを `ねた（あとから）` `おきた（あとから）` として複製（未確認。PC からなら `shl neru 11/7 23:30` で同じことができる）
5. メモも残したい用に 1 個: **入力を要求** → テキスト `［日付］,［数字］,［入力］`（数字は「メニューから選択」で選ばせてもええ）
6. ホーム画面長押し → ウィジェット追加 → ショートカット（大）に全部並べる → **1 タップで記録**

しんどい日にアプリを開く気力がなくても押せるよう、ホーム画面の 1 ページ目に置いとくのがおすすめ。決まった時間に思い出したいなら、オートメーション（時刻）で通知だけ出す手もある。

### Windows
1. Microsoft Store から **iCloud for Windows** を入れて iCloud Drive をオン
2. エクスプローラーの iCloud Drive → `Shortcuts` に `mood.csv` ができてるのを確認（一度 iPhone で記録してから）
3. `mood.csv` を右クリック →「常にこのデバイス上に保持する」（WSL から読むため）
4. `settings.cmd` → `10` にパスを貼り付け（エクスプローラーで Shift+右クリック →「パスのコピー」したものをそのまま）

CSV の 1 行 = `2026-11-01 08:30,-1,だるい`。壊れた行・範囲外の数字・iCloud の重複行は無視する。

## セットアップ

1. `C:\Users\<名前>\shift-lock\` に全部置く（`shiftlock.py` は入口だけで、本体は `shiftlock\` フォルダ。両方要る。リポジトリからなら `deploy.ps1` が両方コピーする）
2. `settings.cmd` で設定（旧版の `shifts.json` はそのまま読める。日付リストの `shifts` も例外の出勤日として扱う）
   - `9` ゲーム判定（下の「ゲーム判定」）
   - `11` Google カレンダー、`12` 例外日
3. Windows（PowerShell）。先に Windows に Python 3.8 以上を入れとく（python.org 版。py launcher も一緒に入る）
   ```powershell
   cd $env:USERPROFILE\shift-lock
   powershell -ExecutionPolicy Bypass -File .\install-task.ps1
   powershell -ExecutionPolicy Bypass -File .\guard.ps1 -TestNotify   # 通知が出るか
   powershell -ExecutionPolicy Bypass -File .\guard.ps1 -DryRun       # 判定が通るか。python= に Windows の Python のパスが出れば OK（wsl なら Python が見つかってへん）
   ```
   旧版（シャットダウンする版）を入れてたら、同じタスク名で上書きされる。
4. WSL
   ```bash
   W=/mnt/c/Users/<名前>/shift-lock
   date                                   # JST になってるか確認
   python3 $W/shiftlock.py install-hook --config $W/shifts.json
   python3 $W/shiftlock.py status --config $W/shifts.json
   ```
   Windows 版 Claude Code も使うなら `--windows-settings /mnt/c/Users/<名前>/.claude/settings.json` を足す（既存の hook はそのまま残る）。
   Claude Code を再起動して `/hooks` で `UserPromptSubmit` と `Stop` に入ってるか確認。旧版の `PreToolUse`（shiftlock のもの）は自動で消える。
5. pwsh のコマンド: `powershell -ExecutionPolicy Bypass -File .\install-profile.ps1`（pwsh 7 と 5.1 の両方のプロファイルに 1 行足す。外すときは `-Uninstall`）

## ゲーム判定

**起動中のプロセスの exe が、ゲームフォルダの中（何階層下でも）にあればゲーム扱い。** 起動してる exe を見て判定するので、ゲームを新しく入れても登録し直す必要はない（定期スキャン不要）。

| 設定（`settings.cmd` → `9`） | 中身 |
|---|---|
| Steam ライブラリ自動 | レジストリと `libraryfolders.vdf` からライブラリを見つけて、各 `steamapps\common` を対象に（Steam 本体の常駐プロセスは対象外） |
| 追加フォルダ | Epic・GOG・手動インストール先など（例 `E:\Games`） |
| 除外フォルダ | ゲーム以外の exe が混ざるフォルダ（例 `E:\Games\Tools`） |
| 除外する名前 | `*Launcher*` みたいなワイルドカード。既定で `UnityCrashHandler*` `CrashReport*` `unins*` `*Redist*` `*Setup*` などを除外 |
| プロセス名で直接指定 | フォルダの外にあるゲーム用（`.exe` は付けても外す） |

確認は `scan-games`（pwsh）か `scan-games.cmd`: 対象フォルダ・除外・ゲームごとの exe 数を表示して、全一覧を `game-scan.txt` に保存。ゲーム以外が混ざってたら除外を足す。`show-games` でいま判定されてるプロセスを見られる。

## 動作要件
- Windows 10 1809 以降。タスクは **Windows PowerShell 5.1（powershell.exe）** で動かす。pwsh 7 から `guard.ps1` を叩いても自動で 5.1 に切り替える（トースト通知の WinRT が pwsh 7 では読めへんため）。`install-task.ps1` は pwsh 7 からでも 5.1 からでも実行できる
- **Windows の Python 3.8 以上**（python.org 版か py launcher。標準ライブラリのみ）。5 分おきの tick と朝のレポートはこれで動く。無ければ WSL の python3 で動くけど、WSL を 5 分おきに起動すると WSLg の RDP クライアントがキー入力を注入して離席中のアイドル秒数が戻るので、Windows に Python を入れるのを勧める（`guard.ps1 -DryRun` の `python=` で確認。issue #22）
- WSL2（既定ディストリに python3 3.8+、標準ライブラリのみ）。Claude Code の hook・`shl`・`*.cmd` はこれで動く。カレンダー同期は tick から HTTPS で取りに行く
- Claude Code hooks（UserPromptSubmit の exit 2 = 拒否、`systemMessage` = ユーザー表示、`additionalContext` = Claude への文脈）

## 既知の制約
- フルスクリーンのゲーム中は Windows の「ゲーム中は通知を止める」設定でトーストが見えへんことがある。気になるなら `notify.nag` を `"popup"` にするか `"speak": true`（読み上げ）。ただし popup はゲームからフォーカスを奪う可能性あり。読み上げは収録中に鳴ると事故るので注意
- ゲームパッド/HOTAS の入力は Windows のアイドル判定に乗らないことがあるので、ゲーム起動中は触ってる扱いにしてる。ただし起動したまま放置すると触ってる扱いが続くので、入力が `usage.game_idle_minutes`（既定 180 分）無ければ離席、『行ってきます』〜『ただいま』の間はゲームを見ない（issue #24）
- Mac（動画編集）は対象外。Python 側はそのまま動くので、launchd ＋ 通知で後から足せる
